## Request flow

Within `src/features/analysis/`, `components/` contains the screen and charts, `use-analysis.ts` coordinates browser-side work, `model/` holds input validation and calculations, `server/` holds database clients, and `data/` holds reference tables. `src/lib/explorer.functions.ts` exposes the server operations to TanStack Start.

1. The analysis screen validates peptides and coordinates searches.
2. TanStack Start server functions submit and poll UniProt peptide-search jobs.
3. The server loads matching UniProt records, retains bacterial hits and extracts protein annotations.
4. The server looks up species classification evidence in BacDive and fallback sources.
5. The browser renders tables/charts and builds downloads. Peptide properties are calculated locally.

The same flow works in development and in the production Node build. External lookups need internet access from the computer running the server.

## Routing

`src/routes/index.tsx` defines the home URL and delegates the analysis screen to the feature folder. `src/routes/__root.tsx` owns the HTML document, shared metadata and error/not-found screens.

`src/routeTree.gen.ts` is generated by the routing plugin. Do not edit it by hand. A nested route needs the root's `<Outlet />` to render.

Read [AGENTS.md](../AGENTS.md) before changing the pipeline or startup setup. Keep scientific-source access in server functions, preserve published Git history, and keep launchers rooted at the project directory.
